# RoadBlockagePlugin.py User Manual

CPWC2026 submission material — "Brief User Manual for the Program"

## Program Overview

RoadBlockagePlugin is a Python plugin that runs inside UC-win/Road (Forum8's driving/road simulation software). It loads a CSV of predicted road-blockage probability (e.g. flooding, closure) per location — a grid of latitude/longitude/probability — and automatically places a **'Barricade'** 3D model as a visual marker on the nearest lane for every point whose probability clears a threshold.

The UC-win/Road Python API has no way to create an actual road obstruction (`F8RoadObstructionProxy`) — it can only read ones that already exist in the road data. The placed Barricades are therefore only a visual marker for *where* a real road obstruction should go; the user places the actual road obstruction manually, using the Barricades as a guide, through UC-win/Road's own road editor.

The plugin also includes a **Traffic Monitor**, which measures and graphs live traffic flow (average speed and vehicle count) around a chosen point in real time. By starting monitoring, removing the visual Barricades, and then manually adding or removing a real road obstruction at that spot in UC-win/Road's own editor, the user can watch how ambient AI traffic actually reacts — through the resulting change in speed and vehicle count.

## How to Run the Program

1. Open the target project in UC-win/Road.
2. **Manually start the simulation (Play mode) first.** Placing a Barricade (`AddNewTransient`) does not initialize correctly unless the simulation is already playing, so Play must be started before the plugin is loaded.
3. Load `RoadBlockagePlugin.py` from UC-win/Road's Python script feature (ribbon or Script Editor), with the **[Async] checkbox turned ON**. The plugin runs a blocking event loop, so leaving [Async] OFF would freeze UC-win/Road. If [Async] is OFF, the plugin detects this, logs a message (also printed to the console), and exits safely without entering the loop.
4. On success, five tabs are added to the UC-win/Road ribbon:
   - **CSV**
   - **Barricades**
   - **Traffic Monitor**
   - **Find Objects**
   - **Reset**
5. To stop, use UC-win/Road's normal script-stop control. The plugin automatically cleans up any placed Barricades, the HUD window, and the ribbon UI on exit.

## Operation Flow

### Loading the CSV generated by RoadBlockDetectionApp.py

1. Beforehand, run `RoadBlockDetectionApp.py` (a separate prediction program from this plugin) to generate a CSV that predicts the blockage probability at each location.
2. In the **CSV** tab, click **"Browse & Load CSV..."**.
3. A native file-open dialog appears (it defaults to the `Prediction` folder if one exists). Select the CSV produced in step 1 (sample outputs are provided under `Prediction/`).
4. The CSV must contain the following columns:
   - `latitude`
   - `longitude`
   - `probability` — blockage probability (0–1)
   - `side_m` — optional, not used for placement

   Any CSV with these columns can be loaded, even if it was not produced by `RoadBlockDetectionApp.py`.
5. On success, a summary label shows "Loaded &lt;filename&gt;: N records, probability x.xxxx-y.yyyy". Rows whose values cannot be parsed as numbers are skipped automatically.

### Placing Barricades (the road obstruction is placed manually at the Barricade's center)

1. In the **Barricades** tab, set:
   - **Probability Threshold** (default 0.7) — only CSV records at or above this probability are placed.
   - **Max Distance to Road (m)** (default 5000) — records farther than this from the nearest road are treated as "not on a road" and skipped.
2. Click **"Place Barricades from CSV"**.
   - Every click deletes all currently placed Barricades and rebuilds the full set from scratch (no incremental update).
   - For each qualifying record, the nearest road and lane are found; two Barricades are then placed **5 m upstream and 5 m downstream** of that center point along the road (two Barricades per record), each automatically rotated perpendicular to the road so it blocks the lane.
   - A summary label reports the results (number placed, number skipped, and why).
3. **The midpoint between the two Barricades marks where the real road obstruction should be placed.** Since the Python API cannot create a road obstruction itself, the user manually places (or moves an existing) real road obstruction at that midpoint using UC-win/Road's own road editor.
4. To check where a placed Barricade actually is, go to the **Find Objects** tab, **Barricades** group, enter a Barricade Index, and click **"Jump to Barricade"** — the main camera moves to that Barricade.
5. In the same **Find Objects** tab, **Road Obstructions** group, click **"List Obstructions"** to list the road obstructions (`F8RoadObstructionProxy`, read-only) already authored in the road data. Enter an Obstruction Index and click **"Jump to Obstruction"** to move the camera there and confirm the manually placed obstruction is where intended.
6. To redo or clean up placements, use the **Reset** tab:
   - **"Reset"** — removes only the Barricades this script placed.
   - **"Clear All"** — a crash-recovery button that unconditionally deletes every transient object in the project; it can also affect ordinary moving traffic, so it is not meant for routine use.

### Displaying the Monitor (visualizing average speed)

1. In the **Traffic Monitor** tab, set:
   - **CSV Record Index** — the index (0-based, in load order) of the CSV record to monitor.
   - **Measurement Radius (m)** (default 50) — vehicles within this radius are measured.
2. Click **"Start Monitoring"**.
   - The nearest road position to that CSV record's latitude/longitude is found and its coordinates are **captured once and fixed** as the monitoring point. This is independent of whether a Barricade exists there, so monitoring continues at the same spot even with no Barricade placed, or after one is removed via **Reset**.
   - A semi-transparent, always-on-top HUD window appears in the lower-right of the screen and tracks UC-win/Road's main window.
3. Every 0.5 seconds, the HUD window and the ribbon's detail box show, live:
   - **Avg Speed (km/h)** — the average speed of vehicles (`TransientCar`) within the radius, plus a line graph of its recent history.
   - **Vehicles in Zone** — the current vehicle count within the radius, plus a line graph of its recent history.
4. Intended workflow:
   1. Click Start Monitoring.
   2. Use **Reset** to remove the visual-only Barricades.
   3. In UC-win/Road's road editor, manually add or remove the real road obstruction at the same spot.
   4. Watch the average speed and vehicle count on the HUD change in response to the AI traffic's actual reaction.
5. Click **"Stop Monitoring"** to end measurement and close the HUD window.
